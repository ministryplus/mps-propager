## What

Port the current PySide6 UI (`ui/overview.py`, `ui/mainwindow.py`, `ui/widget.py`) to native Qt6/C++ as the status window and tray menu for ProPager. This is step 6 of the Implementation Sequence. The window is a `QMainWindow` titled `ProPager` (Decision 11) showing the active number, the queued-numbers list, and a status bar reporting Slack and ProPresenter connection state; the tray is a `QSystemTrayIcon` + `QMenu` mirroring that state with Open Window and Quit actions. The single hard constraint is Decision 7: every UI update arrives as a **direct Qt signal/slot connection** from `SlackClient`, `ProPresenterClient`, and `PagerController`. The `poll_in_thread` status-polling thread in `overview.py` — which reached into `client.number_queue._queue` on a background thread — is **removed**, not ported. This task also owns the `main.cpp` wiring for the UI feature so that Task 7 never needs to touch `main.cpp`.

## Steps

1. Create `src/ui/mainwindow.{h,cpp}` — a `QMainWindow` subclass titled `ProPager` (was `"Village Kids Pager"`), resized to roughly the current 300x200. Central widget lays out (ports `overview.py`):
   - An **Active Number** label (`"Active Number: N/A"` initially).
   - A **Numbers Queued** label/list (`"Numbers Queued:"` initially), newline-joined.
   - A `QStatusBar` with two permanent widgets: `Slack: Disconnected` and `ProPres: Disconnected`.
2. Create `src/ui/traymenu.{h,cpp}` — a `QSystemTrayIcon` + `QMenu` (ports `widget.py`) with, in order: a disabled ProPresenter-status action, a disabled Slack-status action, a separator, a disabled active-number line, a separator, an **Open Window** action (raises/shows the main window), and a **Quit** action (`qApp->quit()`). This **supersedes the placeholder tray created in Task 1** — move that tray wiring out of `main.cpp` step 1 and into this class.
3. **Remove the poll thread (Decision 7).** Do not port `poll_in_thread`. Instead expose slots on both the window and the tray and connect them directly:
   - `SlackClient::connected()` / `SlackClient::disconnected()` → set the Slack status labels/actions to `Slack: Connected` / `Slack: Disconnected`.
   - `ProPresenterClient::connected()` / `ProPresenterClient::disconnected()` → set the ProPresenter status labels/actions to `ProPres: Connected` / `ProPres: Disconnected`.
   - `PagerController` signals → the active formatted number, the last number, and the queued batches list. (Coordinate exact signal names/signatures with Task 001-4; if a needed signal is absent, add it to the controller rather than reaching into its internals.)
4. Preserve the current formatting exactly:
   - `"Active Number(s): {formatted}"` — pluralize to `"Active Numbers:"` when the active batch has more than one number, and `"Active Number:"` otherwise (matches the `len(_current_nonce) > 1` logic in `overview.py`); show `"Active Number: N/A"` when nothing is active.
   - A `"Last Number: {n}"` line prepended above the active line when a last number exists.
   - The queue rendered as `"Numbers Queued:\n{newline-joined batch strings}"`, including the currently-forming batch, using the same per-batch formatting the controller uses.
5. Port the setup-error alert surface from `mainwindow.py`: a slot (e.g. `showSetupError(const QString&)`) that pops a critical `QMessageBox` (title `Error!`) for config/connection errors. (The `confirm_creation_dialog` from `mainwindow.py` is **not** ported — Decision 5 makes ProPager create/own its message automatically, so no confirm dialog.)
6. Ensure closing the window hides it to the tray instead of quitting (override `closeEvent` to `ignore()` + `hide()`), so the app keeps running in the tray; only **Quit** exits.
7. Wire it all up in `src/main.cpp`: construct the window and tray, pass in references to the `SlackClient`, `ProPresenterClient`, and `PagerController`, and make the signal/slot connections from step 3. **Task 7 must not touch `main.cpp`** — all UI wiring lives here.
8. Update `CMakeLists.txt` to add the four new UI sources to the target.

## Acceptance Criteria

- [ ] `src/ui/mainwindow.{h,cpp}` exists: a `QMainWindow` titled `ProPager` with an Active Number label, a Numbers Queued list, and a status bar showing Slack and ProPresenter connection state.
- [ ] `src/ui/traymenu.{h,cpp}` exists: a `QSystemTrayIcon` + `QMenu` with ProPresenter status, Slack status, an active-number line, Open Window, and Quit.
- [ ] The Task 1 placeholder tray is removed from `main.cpp`; its wiring now lives in `traymenu`.
- [ ] No polling thread exists — no `QThread`, `std::thread`, or busy-loop in the UI; all updates are direct signal/slot connections from `SlackClient`, `ProPresenterClient`, and `PagerController`.
- [ ] Status labels/actions flip between `Connected` and `Disconnected` driven by the clients' `connected()`/`disconnected()` signals.
- [ ] Active/last/queued lines update from controller signals and match the `overview.py` formatting (singular/plural, `Last Number:` line, newline-joined queue).
- [ ] A setup-error `QMessageBox` surface is available and triggered by config/connection errors.
- [ ] Closing the window hides it to the tray; **Quit** exits the app.
- [ ] All UI signal/slot wiring lives in `main.cpp`; Task 7 does not modify `main.cpp`.

## Open items (decide during this task)

- **Modal vs. transient errors.** Both clients emit `error(QString)` for
  *transient* failures too — Slack reconnect-backoff attempts, a failed
  `reactions.add`, a ProPresenter request that times out — not just fatal
  config/setup problems. Routing *every* such error to the modal
  `showSetupError` `QMessageBox` (step 5) would spam the user during a network
  blip. Decide here: reserve the modal for fatal setup/config errors, and
  surface transient errors more quietly (status-bar text, or an in-window
  message line) instead.
- **In-app log / activity view (currently absent).** The spec provides a log
  *file* only (Decision 10 / TODO 2, under the app-support/`ProPager` dir);
  there is no log pane or "view logs" affordance anywhere in the UI. Consider
  whether a lightweight in-window activity/log view (or at minimum a menu action
  that reveals the log file in Finder) is worth adding — this is the natural
  place for it, and it pairs well with the transient-error decision above.

## Verification

Concrete end-to-end check:

1. Build and launch the app. Confirm both a tray icon and (on request) the status window appear, titled `ProPager`.
2. With no clients connected, both the tray menu and the status bar show `Slack: Disconnected` and `ProPres: Disconnected`.
3. Connect each client (or emit its `connected()` signal): the corresponding tray action **and** status-bar label flip to `Connected`; on disconnect they flip back. Confirm this happens live, without any restart.
4. Feed numbers through the `PagerController` (single and multi-number batches): the **Active Number(s)** line updates in real time with correct singular/plural, a `Last Number:` line appears once a number has shown, and the **Numbers Queued** list reflects queued batches newline-joined.
5. Trigger a config/connection error and confirm the critical `QMessageBox` appears with title `Error!`.
6. Close the status window and confirm the app stays alive in the tray (icon still present, no process exit); then choose **Quit** and confirm the process exits.
7. `grep -rE 'QThread|std::thread' src/ui src/main.cpp` returns **no** matches — proving the poll thread was removed and updates are pure signal/slot.
